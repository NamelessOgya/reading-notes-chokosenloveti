## 一言まとめ
超巨大言語モデル（Gemini 等）の知識をコンパクトなリトリーバー（1.2B / 768次元）へと蒸留（Distillation）する汎用テキスト埋め込みモデル。Web パッセージからの多様なクエリ生成と、生成質問に対する「真の正例・ハード負例」の LLM 再ラベリング（Relabeling）を統合した **2段階蒸留データセット「FRet（660万件）」** を開発。MTEB において、7倍巨大な 7B パラメータモデル（E5-Mistral 等）や 4,096 次元モデル群に匹敵する **66.31 pt（当時の 768 次元帯で世界 1 位）** を達成した。

---

## 背景

2023年〜2024年初頭のテキスト埋め込みモデルの主流は、Mistral-7B などの巨大デコーダ LLM をそのままファインチューニングするアプローチ（E5-Mistral, GRITLM 等）であった。しかし、これらのモデルは以下のような実用上の大きな課題を抱えていた：
1. **推論コストとレイテンシの増大**: 7B モデルのエンコードは大量の GPU メモリを消費し、実検索システムの QPS（秒間クエリ数）に耐えにくい。
2. **ベクトル次元の肥大化**: 4,096 次元もの高次元ベクトルは、ベクトル検索インデックス（HNSW / ScaNN 等）のメモリ消費量を激増させる。

Google の研究チームは、「**LLM の卓越した世界知識と推論能力を、わずか 1.2B・768 次元（さらに 256 次元）のコンパクトなエンコーダに知識蒸留できないか？**」という問いに取り組み、本モデル **Gecko** を開発した。

## 手法（再現可能な詳細仕様）

### 1. 2段階 LLM 蒸留データセット「FRet (Few-shot Prompted Retrieval)」

Gecko の中核を成すのは、Web コーパスから LLM を用いて作成した 660 万件の合成データセット **FRet** である。

```
[Webパッセージ (p_seed)] 
       │
       ▼ Step 1: LLM による多様なタスク・クエリ生成 (P_QG)
[タスク指示文 (t) + 検索質問 (q)]
       │
       ▼ 近傍パッセージ検索 (Top-N 件取得)
[候補パッセージ群: p_1, p_2, ..., p_N]
       │
       ▼ Step 2: LLM による正例・負例の再ラベリング (Relabeling)
         ・Query Likelihood (尤度判定: P_QL)
         ・Relevance Classification (関連度判定: P_RC)
         ・Reciprocal Rank Fusion (RRF) で統合
       │
┌──────┴───────────────────────────────────────┐
│ 最上位パッセージ ──> 新しい真の正例 (p+)       │
│ ※ 元の p_seed と異なるケースが約 15% 存在！    │
│ 最下位パッセージ ──> 高品質なハード負例 (p-)    │
└──────────────────────────────────────────────┘
```

#### Step 1: 多様なタスク・クエリ生成 (Query Generation)
- Web からランダム抽出したパッセージ $p_\mathrm{seed}$ に対し、Few-shot プロンプト $\mathbb{P}_\mathrm{QG}$ を用いて、タスク説明文 $t$（QA、事実検証、検索等）と質問文 $q$ を生成：
  $$(t, q) \sim \operatorname{LLM}(p_\mathrm{seed}, \mathbb{P}_\mathrm{QG})$$
- 自由形式のタスク説明文 $t$（例: *"Given a query, find a passage that has the answer to the query"* や *"Given a query, find a passage that allows you to check whether the query is true or not"*）を生成させることで、クエリの言語的・意図的多様性を最大化。

#### Step 2: 正例・ハード負例の LLM 再ラベリング (Relabeling & Mining)
- **従来の盲点**: 従来の合成手法（Promptagator, InPars 等）は、質問を生成した元の $p_\mathrm{seed}$ をそのまま正例としていた。
- **Gecko の着眼点**: 生成された質問に対して、Web 全体を探せば**元の $p_\mathrm{seed}$ よりも遥かに直接的で適切な正解パッセージが存在するケースが約 15% もある**（Table 5 の定性分析参照）。
- **アルゴリズム手順**:
  1. 生成されたクエリ $q$ に対し、初期埋め込みモデルを用いて Web コーパスから Top-$N$ 件（$N=20$）の近傍文書を取得：$P = \{p^{(1)}, \dots, p^{(N)}\}$。
  2. LLM の 2 つの Few-shot プロンプトで各パッセージをスコアリング：
     - **Query Likelihood ($\mathbb{P}_\mathrm{QL}$)**: パッセージからクエリが生成される対数尤度 $\operatorname{QL}(q, p) = \log P(q \mid p, \mathbb{P}_\mathrm{QL})$
     - **Relevance Classification ($\mathbb{P}_\mathrm{RC}$)**: 関連度ラベル（0〜3）の対数事後確率 $\operatorname{RC}(q, p) = \log P(\text{label} \mid q, p, \mathbb{P}_\mathrm{RC})$
  3. 2つのランキングを **Reciprocal Rank Fusion (RRF)** で統合：
     $$R(q, p) = \frac{1}{r_\mathrm{QL}(q, p)} + \frac{1}{r_\mathrm{RC}(q, p)}$$
  4. **新正例 $p^+$ の決定**: RRF で 1 位となった最も関連性の高いパッセージを採用：
     $$p^+ = \arg\max_{p \in P} R(q, p) = p_1$$
  5. **ハード負例 $p^-$ の決定**: RRF で最下位（20位）となった類似しているが不適合なパッセージを採用：$p^- = p_{20}$。

---

### 2. 統一エンコーディングフォーマット（Unified Formatting）

タスク間の干渉を防ぎ、モデルにタスクの対称性・非対称性を正しく認識させるため、入力とターゲットを以下の厳密な統一フォーマットで前処理：

- **対称タスク（STS、文類似度、分類ペア等）**:
  - `Input  = task: {task} | query: {input}`
  - `Target = task: {task} | query: {target}`
- **非対称タスク（検索、QA、事実検証等）**:
  - `Input  = task: {task} | query: {input}`
  - `Target = title: {title} | text: {target}`

※この統一フォーマットを崩してナイーブに文字列連結すると、MTEB 平均スコアが **-3.4 pt 激減** することがアブレーションで証明されている（Table 4）。

---

### 3. 分類データの対照学習化（Unique ID トリック）

分類タスク（Sentiment, Intent, Topic等）を対照学習に組み込む際、同一ラベルを持つ文同士を正例ペア $(x, x^+)$、別ラベルの文を負例 $x^-$ とする。
- **バッチ内偽陰性（False Negative）問題**: バッチサイズが大きい場合、同一バッチ内に同じクラスラベルを持つ別サンプルが存在すると、それが負例として誤ってペナルティを受けてしまう。
- **Gecko の解決策**: 各トリプル $(x, x^+, x^-)$ に対してランダムな固有の「**Unique ID**」を発行し、テキスト末尾に同一の ID を付与。これにより、ID が一致しないバッチ内の他サンプルはモデルにとって自明に「別グループ（無関係）」と識別可能になり、純粋に $x$ に対する $(x^+, x^-)$ の識別学習に集中させることができる。

---

### 4. 2段階学習パイプラインと目的関数

1. **ベースモデル**: 1.2B パラメータの事前学習済み双方向 Transformer 言語モデル（Mean Pooling 採用）。
2. **Pre-finetuning（事前ファインチューニング）**:
   - コミュニティ QA サイトのペア（Ni et al., 2021）＋ Web のタイトル-本文ペアを用いた大規模対照学習。タスク指示文 $t$（`"question answering"` 等）をクエリに前置し、大バッチ（In-batch 負例のみ）で学習。
3. **Unified Fine-tuning（本学習）**:
   - FRet（6.6M）＋ 学術データセット（Natural Questions, HotpotQA, FEVER, MedMCQA, SNLI, MNLI, MIRACL 等）＋ 分類データセットを統合。
4. **Same-tower negatives（同一タワー負例）の導入**:
   - 通常のパッセージ負例に加え、**同一バッチ内の他のクエリ $\{q_j\}_{j \neq i}$ も負例として分母に含める**損失関数を採用（Moiseev et al., 2023）：
     $$\mathcal{L}_\mathrm{main} = -\frac{1}{B}\sum_{i=1}^B \log \frac{\exp(\operatorname{sim}(\mathbf{q}_i, \mathbf{p}_i^+) / \tau)}{\sum_{j=1}^B \exp(\operatorname{sim}(\mathbf{q}_i, \mathbf{p}_j^+) / \tau) + \sum_{j \neq i} \exp(\operatorname{sim}(\mathbf{q}_i, \mathbf{q}_j) / \tau) + \exp(\operatorname{sim}(\mathbf{q}_i, \mathbf{p}_i^-) / \tau)}$$
   - クエリ同士（同一タワー）の弁別を強制することで、対称な文類似度（STS）の幾何学的歪みを解消。
5. **Matryoshka Representation Learning (MRL)**:
   - 先頭 256 次元と 768 次元の 2 段階でマルチロス学習を実施。単一モデルで 256 次元の超軽量埋め込みを切り出し可能。

### スコア考察
1. **圧倒的なサイズ・次元対効果**:
   - `gecko-1b-768`（1.2B / 768次元）は **66.31 pt** を記録し、同サイズ帯の `gtr-t5-xl`（58.42）や `instructor-xl`（61.79）を粉砕。OpenAI text-embedding-3-large（64.59）を上回り、7倍巨大な 7B モデル（66.6〜66.7 pt）に肉薄。
2. **256 次元での驚異的性能**:
   - `gecko-1b-256` は **64.37 pt** を達成し、OpenAI の 256 次元版（62.00）を大きく凌駕。OpenAI のフル 3,072 次元（64.59）と同等の精度を 1/12 のベクトルサイズで実現。
3. **純粋な合成データ（FRet のみ）の強さ**:
   - 人手ラベルデータを一切使わず、FRet のみで学習したゼロショット Gecko でも **62.64 pt** を記録し、既存の多くの中型モデルを上回った。

## 貢献と限界

### 貢献
- **LLM から小型エンコーダへの知識蒸留を確立**: 1.2B・768 次元で 7B・4,096 次元級の表現力を達成し、産業利用（高速推論・低メモリ）における最高水準の基盤を提供。
- **FRet パイプラインの発明**: 「元のパッセージを疑い、LLM で正例を再採掘する」という手法は、その後のテキスト埋め込み研究におけるデータ生成の標準となった。
- **商用 Vertex AI API（text-embedding-004/005）への社会実装**: 検索、RAG、類似度計算で世界中のエンタープライズに広く利用された。

### 限界と Gemini Embedding への進化
- **蒸留の限界**: 1.2B というモデル容量の制約上、複雑な長文推論や極端な低リソース言語（XTREME-UP 等）では限界が存在した。
- **Same-tower 負例のトレードオフ**: クエリ同士を負例にする手法は STS に効く一方、分類タスク等で偽陰性（False Negatives）を引き起こしやすい弱点があった。
- $\to$ これらの課題を受け、Google は 2025 年に**蒸留をやめて Gemini デコーダ本体を直接双方向エンコーダ化し、FRet 手法を分類・フィルタリングまで全面拡張した「Gemini Embedding」**を発表することとなる。
