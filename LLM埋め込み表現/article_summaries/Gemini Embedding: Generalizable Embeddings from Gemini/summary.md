# Gemini Embedding: Generalizable Embeddings from Gemini

**arXiv:** 2503.07891  
**著者:** Google DeepMind（Gemini Embedding Team: Jinhyuk Lee, Feiyang Chen, Sahil Dua, Daniel Cer, Madhuri Shanbhogue 他）  
**発表:** 2025年3月  

---

## 一言まとめ
Google のフロンティア基盤モデル「Gemini」をバックボーンとして活用し、因果的デコーダから双方向エンコーダへのアーキテクチャ転換、大バッチ Pre-finetuning と小バッチ Fine-tuning の 2 段階学習パイプライン、Gemini 自身による合成データ生成・品質フィルタリング・RRF ハード負例採掘、およびモデルスープ（Model Soup）による重み融合を統合した汎用テキスト埋め込みモデル。英語 MTEB v2（73.3 pt）、MTEB Code（75.5 pt）、多言語 MMTEB（68.3 pt）、低リソース言語 XTREME-UP（64.3 pt）の全主要ベンチマークで世界 1 位を達成。

---

## 背景

汎用テキスト埋め込みモデルの究極の目標は、単一の表現空間で「あらゆる言語（250言語以上）」「あらゆるドメイン（Web、コード、学術等）」「あらゆるタスク（検索、分類、STS、クラスタリング）」に対応することである。

従来のアプローチ（BERT系エンコーダや小規模モデルの蒸留）では、低リソース言語や複雑なコード検索、未知タスクへの汎化能力に限界があった。Google DeepMind は、Gemini の膨大な世界知識・高度な推論力・多言語ネイティブ能力をそのまま密ベクトル表現へと変換する **Gemini Embedding** を開発した。

## 手法（再現可能な詳細仕様）

### 1. モデルアーキテクチャと埋め込み抽出

Gemini Embedding は、事前学習済み Gemini デコーダを基盤とし、以下の変換を経て密ベクトルを生成する。

```
[入力テキスト + タスク指示文] 
       │
       ▼
┌───────────────────────────────────────────────────────────┐
│ Gemini Transformer (Causal Mask を解除した双方向アテンション) │
└───────────────────────────────────────────────────────────┘
       │  トークン埋め込み系列: T_embed ∈ R^(L × d_M)
       ▼
┌───────────────────────────────────────────────────────────┐
│ Mean Pooling (系列長 L の全トークン平均)                     │
└───────────────────────────────────────────────────────────┘
       │  集約ベクトル: P_embed ∈ R^(d_M)
       ▼
┌───────────────────────────────────────────────────────────┐
│ ランダム初期化 Linear Projection (f)                      │
└───────────────────────────────────────────────────────────┘
       │  出力ベクトル: E ∈ R^d  (最大 d = 3,072)
       ▼
┌───────────────────────────────────────────────────────────┐
│ Matryoshka Representation Learning (MRL)                  │
│ [ 768次元 ] / [ 1,536次元 ] / [ 3,072次元 ]                 │
└───────────────────────────────────────────────────────────┘
```

1. **双方向アテンション（Bidirectional Attention）への転換**:
   - 元の自己回帰型（Causal）因果マスクを撤廃し、全トークンが前後双方向の文脈を参照できるように変更（$\mathcal{M}$）。
2. **プーリング戦略（Mean Pooling）**:
   - 先行研究（Suganthan et al., 2025）に基づき、複雑なプーラー（EOSプーリングやLatent Attention等）ではなく、系列軸に沿った**単純平均プーリング（Mean Pooling）**を採用：
     $$\mathbf{P}_\mathrm{embed} = \operatorname{mean\_pool}(\mathbf{T}_\mathrm{embed}) = \frac{1}{L} \sum_{l=1}^L \mathbf{T}_{\mathrm{embed}, l} \in \mathbb{R}^{d_\mathcal{M}}$$
3. **線形射影層（Linear Projection Layer）**:
   - ランダム初期化された線形変換 $f$ を通して、目標の埋め込み次元 $d = 3,072$ にスケーリング：
     $$\mathbf{E} = f(\mathbf{P}_\mathrm{embed}) \in \mathbb{R}^d$$
4. **Matryoshka Representation Learning (MRL)**:
   - 先頭 768 次元、1,536 次元、3,072 次元の $k$ 個のネストした部分次元それぞれに対して個別に損失を計算するマルチロス学習を実施。単一モデルで 768 / 1536 / 3072 次元の柔軟な切り出し・ベクトル圧縮を可能にしている。

---

### 2. タスク指示文（Task String）の非対称設計

タスクの性質を指定するため、クエリ側のみにタスク文字列 $t$（例: `"question answering"`, `"fact checking"`）をプレフィックス結合し、パッセージ側には付与しない**非対称エンコーディング**を採用：

- **クエリ側**: $\mathbf{q}_i = f(\operatorname{mean\_pool}(\mathcal{M}(t \oplus q_i)))$
- **パッセージ側（正例 / 負例）**: $\mathbf{p}_i^\pm = f(\operatorname{mean\_pool}(\mathcal{M}(p_i^\pm)))$

---

### 3. 損失関数（NCE 損失 with クラス重複マスキング）

ミニバッチサイズ $B$ に対し、以下の改良型 InfoNCE（Noise-Contrastive Estimation）損失を適用：

$$\mathcal{L} = \frac{1}{B} \sum_{i=1}^B \left[ -\log \frac{\exp(\operatorname{sim}(\mathbf{q}_i, \mathbf{p}_i^+) / \tau)}{\exp(\operatorname{sim}(\mathbf{q}_i, \mathbf{p}_i^-)/\tau) + \sum_{j=1}^B \operatorname{mask}(i,j) \exp(\operatorname{sim}(\mathbf{q}_i, \mathbf{p}_j^+) / \tau)} \right]$$

- **類似度関数**: コサイン類似度 $\operatorname{sim}(\mathbf{x}, \mathbf{y}) = \frac{\mathbf{x}^\top \mathbf{y}}{\|\mathbf{x}\| \|\mathbf{y}\|}$
- **False Negative 防止用マスキング項 $\operatorname{mask}(i,j)$**:
  $$\operatorname{mask}(i,j) = \begin{cases} 0 & \text{if } q_i = q_j \text{ または } p_i^+ = p_j^+ \\ 1 & \text{otherwise} \end{cases}$$
  - **重要性**: ラベル数が少ない分類タスク等において、同一バッチ内に「同じ正解クラス」を持つサンプルが存在する場合、それを負例としてペナルティを与えてしまう（偽陰性ペナルティ）のを完全にマスクして防ぐ。
- **ハード負例項**: ハード負例 $p_i^-$ が与えられないフェーズ（Pre-finetuning等）では分母の第1項を省略。
- **同一タワー負例（Same-tower negatives）の明示的排除**: 先行研究 Gecko ではクエリ同士・文書同士を負例とする同一タワー負例を用いていたが、偽陰性の害が利益を上回ることが判明したため、Gemini Embedding ではあえて排除。

---

### 4. 2段階学習パイプライン（Training Recipe）

Gemini の生成能力をエンコーダに安全に適応させるため、明確に役割分担された 2 段階学習を採用。

| 項目 | Stage 1: Pre-finetuning | Stage 2: Fine-tuning |
| :--- | :--- | :--- |
| **主目的** | 自己回帰生成から双方向エンコーディングへの表現適応 | タスク・言語・コードの精密な識別能力と境界学習 |
| **学習データ** | 10億規模（Billion-scale）Webコーパス（タイトル-本文ペア） | 精選されたマルチタスク三つ組（Query, Positive, Hard Negative） |
| **ハード負例** | なし（In-batch 負例のみ） | あり（Gemini RRF 採掘負例） |
| **バッチサイズ** | **大バッチサイズ（Large Batch）**<br>※ノイズの多いWebデータの勾配を安定化 | **小バッチサイズ（< 1024）**<br>※タスク特化のシグナルを先鋭化 |
| **バッチ構成** | 多様なデータを混交 | **単一データセット限定バッチ（Dataset-homogeneous）**<br>※異種タスク（検索と分類等）を同一バッチで混ぜない |
| **学習ステップ** | **非常に大規模（長ステップ）** | 相対的に少ステップ（早期収束） |

### 5. Gemini 自身を活用したデータ品質向上（3大パイプライン）

![Figure: ハード負例マイニングのプロセス](./images/hn_mining_performance_img.png)

#### ① LLM 自己合成データ生成（Synthetic Data Generation / Self-training）
- **検索タスク (Retrieval)**:
  - FRet / SWIM-IR のプロンプティングを拡張。Webパッセージから Few-shot で合成クエリを自動生成し、Gemini Auto-rater で「非現実的な検索クエリ」を自動判定・除去。
- **分類タスク (Classification)**:
  - 反実仮想（Counterfactual）、感情分析、レビュー極性判定などのデータを Zero-shot 合成。
  - **階層的マルチステージプロンプト (Multi-stage Prompting)**: 「架空のユーザープロファイル」や「製品・映画のメタ情報」を先に生成（コンディショニング）してから本文を生成。
  - **テールのサンプリング (Sampling from the tail)**: 長い生成候補リストの末尾からサンプリング。生成リストの後ろに行くほど多様性が自然に増大する現象を利用し、データの多様性を最大化。
  - **効果**: 分類タスク平均が **57.57 $\to$ 75.17 (+17.6 pt)** へ爆発的に向上（Table 6）。

#### ② データフィルタリング（Data Filtering）
- 人手アノテーションデータや既存ベンチマークの訓練セット（MIRACL 18言語等）に潜む「誤った正例」や「無関係な負例」を Few-shot 評価プロンプトで検知し、不良サンプルを除外。
- MIRACL 18言語の平均検索スコアが **59.8 $\to$ 63.7 (+3.9 pt)** へ向上。

#### ③ RRF ハード負例マイニング（Hard Negative Mining）
1. ハード負例なしで学習した初期 Gemini Embedding モデルを用意。
2. 各クエリに対して Top-$k$ 近傍パッセージを検索。
3. 取得したパッセージを Gemini による 2 つのプロンプティング戦略でスコアリング：
   - **Graded Classification**: 段階的な関連度判定（0〜3など）。
   - **Query Likelihood**: クエリが生成される尤度。
4. 2つのスコアを **Reciprocal Rank Fusion (RRF)** で統合。
5. **最重要知見**: RRF スコアでソートされた「最も関連度が低い近傍文書（$k$ 番目の近傍）」が、最も効果的なハード負例として機能。過剰なハード負例は過学習（Overfitting）を招くため、適切な件数（1〜数件）に制限。

### 6. モデルスープ（Model Soup）による重み融合

単一の最終チェックポイントを採用せず、以下の重み平均化を適用：
- 同一ラン内の複数チェックポイント平均（SWA）。
- 異なるデータ混合比（英語特化、多言語特化、コード特化）で学習した異種ラン間の重み平均。
- 目的関数に応じた重み付け平均（Weighted Average）。

タスク間の干渉（Negative Transfer）を起こすことなく、英語（MTEB v2: 73.3）、コード（Code: 75.5）、多言語（XTREME-UP: 64.3）の全ドメインで最高性能を単一モデルに集約した。

#### 各手法の効果の分析・考察:
1. **Pre-finetuning の絶大な効果**:
   - 初期重み（No Training: 9〜30 pt）から Web ペアの大バッチ対照学習を挟むだけで、全ベンチマークが **+20〜36 pt 向上**。自己回帰デコーダの重みが双方向エンコーダ表現へと完全に適応した。
2. **単一特化モデルにおけるタスク競合（Task Conflict）**:
   - `English Only` は英語（72.77）に強いが、コード（58.68）や低リソース言語（49.34）が大きく犠牲になる。
   - `Code Only` はコード（72.08）に強いが、低リソース言語（34.74）は壊滅的に低下する。
3. **Model Soup による「いいとこ取り（トレードオフの完全克服）」**:
   - 各特化モデルの重みをマージした **Gemini Embedding** は、英語（73.28）、コード（74.66）、多言語（68.32）のすべてにおいて、**各特化モデル単体の最高スコアをさらに上回る（Super-additive）驚異的な性能**を達成。低リソース言語でも多言語特化モデル（65.06）に肉薄する 64.33 を維持。

## 貢献と限界

### 貢献
- **最高峰 LLM の直接エンコーダ化**: 蒸留や縮小モデルに頼らず、Gemini デコーダそのものを双方向エンコーダ化する体系的レシピの確立。
- **データ・モデル両面での Gemini の活用**: 合成データ生成（テールサンプリング）、LLM品質フィルタリング、RRFハード負例採掘を定式化。
- **世界 1 位の汎化性能**: 英語・コード・多言語・低リソース言語の全主要ベンチマークで圧倒的 SOTA を達成。

### 限界
- **パラメータ規模と推論コスト**: 数百M規模のエンコーダ（ModernBERT / Ruri 等）に比べ、Gemini 基盤であるため推論レイテンシや GPU/TPU メモリ消費が大きい。
- **一部ハイパーパラメータの秘匿性**: ベースとなった Gemini の具体モデルサイズ（パラメータ数）、厳密な学習ステップ数や学習率などは非公開。
