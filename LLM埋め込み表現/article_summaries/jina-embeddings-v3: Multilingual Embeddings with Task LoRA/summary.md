# jina-embeddings-v3: Multilingual Embeddings with Task LoRA

**arXiv:** 2409.10173  
**著者:** Saba Sturua*, Isabelle Mohr*, Mohammad Kalim Akram*, Michael Günther*, Bo Wang*, Markus Krimmel, Feng Wang, Georgios Mastrapas, Andreas Koukounas, Nan Wang, Han Xiao（Jina AI）  
**発表:** EMNLP 2024 / 2024年9月  

---

## 一言まとめ
複雑なプロンプトや指示文（Instruction）の代わりに、わずか3%の追加パラメータである「5つのタスク特化 LoRA アダプター（Task LoRA）」を切り替えることで、検索・STS・分類・クラスタリングに最適化された高品質ベクトルを生成する多言語・長文対応（8,192トークン）テキスト埋め込みモデル。英語・多言語 MTEB において OpenAI や Cohere の商用 API を上回る SOTA を達成。

---

## 背景

汎用テキスト埋め込みモデルは、対称な類似度判定（STS）と非対称な情報検索（Query $\leftrightarrow$ Passage）で求められる表現空間の幾何構造が根本的に異なる。これに対し、従来のモデルは以下のアプローチを取ってきた：
1. **InstructOR / E5 などの指示文（Instruction-tuning）**:
   - `Represent the query for retrieving relevant documents:` などのプレフィックスを文頭に付与する方式。
   - プロンプトの言い回しに精度が過敏に依存し、有効な指示文の設計が難しい。
2. **7B〜8B 規模の LLM ベース埋め込み**:
   - 表現力は高いが、推論レイテンシ・VRAM 消費・出力次元（4096次元）が肥大化し、実運用の RAG システムには重すぎる。

Jina AI は、**570M パラメータの多言語エンコーダ（XLM-RoBERTa 拡張）に軽量な「Task LoRA アダプター」を統合** することで、指示文なしでタスク ID を渡すだけで最適な埋め込み空間を動的に切り替える新しいアーキテクチャを提案した。

## 手法

### 1. モデルアーキテクチャ仕様

- **ベースモデル**: XLM-RoBERTa（559M / 24層 / 250k 語彙）
- **長文対応**: RoPE（Rotary Position Embeddings）を採用し、コンテキスト長を **8,192 トークン** に拡張（学習時 base 10,000 $\to$ 推論時 20,000 に調整）。
- **高速化**: FlashAttention-2 を統合。
- **プーリング**: Mean Pooling。
- **MRL（Matryoshka Representation Learning）**: 1024次元から 512 / 256 / 128 / 64 / 32 次元へ自在に切り詰め可能。

---

### 2. 5つの Task LoRA アダプター

Multi-Head Attention の線形層に Rank=4 の LoRA レイヤー（総パラメータのわずか 3% / 13M）を配置し、タスクに応じて切り替える：

| アダプター名 | 対象タスク | 目的・幾何学的特性 |
|---|---|---|
| `retrieval.query` | 非対称検索（クエリ側） | 質問・検索文の意図を抽出し、ドキュメント空間とマッチする表現へ変換 |
| `retrieval.passage` | 非対称検索（文書側） | 長文ドキュメントの要点・文脈を網羅的に凝縮 |
| `separation` | クラスタリング・リランキング | ドメインやトピックごとのクラスタ分離度（v-measure）を最大化 |
| `classification` | テキスト分類 | クラス境界を明確にする表現空間を形成 |
| `text-matching` | 対称検索・STS・文一致 | 同一形式のテキスト間の意味的近傍性（コサイン類似度）を精密化 |

---

### 3. 合成データによる 4大検索エラーのパッチ（Correction）

検索モデルで頻発する以下の4つの代表的失敗ケースに対し、合成データ（Synthetic Data）を生成してファインチューニングに注入：
1. **語彙重複の罠（Lexical Bias）**: 単語が重複しているが無関係な負例を正例と誤認するエラーを修正。
2. **否定表現の見落とし（Negation Error）**: `not`, `never` などの否定詞による意味反転を正しく識別。
3. **数値・日付の不一致（Temporal/Numerical Error）**: 年号や金額の誤照合を防止。
4. **エンティティの混同（Named Entity Confusion）**: 同姓同名や類似組織の混同を解消。

---

### 4. 3段階学習パイプライン

1. **Stage 1 (MLM Pre-training)**: CulturaX コーパス（89言語、英語約20%）を用いた MLM 事前学習（512長 100k ステップ $\to$ 8,192長 60k ステップ）。
2. **Stage 2 (Embedding FT)**: 多言語テキストペアによる対照学習（Mean Pooling 導入）。
3. **Stage 3 (Task LoRA FT)**: 各タスク専用のデータセットと専用損失（InfoNCE, MRL, 分類損失）を用い、5つの LoRA アダプターを独立・最適化。

## 貢献と限界

### 貢献
- **Task LoRA によるタスク特化表現の確立**: 指示文設計の手間をゼロにし、API からタスク ID を指定するだけで最適な空間へ誘導。
- **商用 API を凌駕する 570M 効率モデル**: OpenAI ada-002 / text-embedding-3-large や Cohere を MTEB で上回る。
- **8,192 トークン長文対応**: RoPE 調整と FlashAttention2 による高速・高精度な長文検索。
- **MRL 対応**: 32〜1024次元の柔軟なダウンサイジング。

### 限界
- **タスク ID の事前指定が必要**: クエリ入力時にどのタスクアダプターを使用するかを呼び出し側が明示的に指定する必要がある。
- **多言語の極小リソース言語**: 89言語対応だが、主要言語に比べ超低リソース言語の精度には開きがある。
