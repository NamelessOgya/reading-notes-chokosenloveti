# Adapting Decoder-Based Language Models for Diverse Encoder Downstream Tasks (Gemma Encoder)

**arXiv:** [2503.02656](https://arxiv.org/abs/2503.02656)  
**著者:** Paul Suganthan, Fedor Moiseev, Le Yan, Junru Wu, Jianmo Ni, Jay Han, Imed Zitouni, Enrique Alfonseca, Xuanhui Wang, Zhe Dong（Google / Google Research / Google DeepMind）  
**発表:** 2025年3月  

---

## 一言まとめ
事前学習済みデコーダ LLM（Gemma-2 2B / 9B）を分類・回帰・ランキングなどの判別的エンコーダタスクへ適応させる体系的設計手法（**Gemma Encoder**）を確立した研究。追加の事前学習（MLM uptraining 等）なしに、因果マスク解除（双方向アテンション化）＋ 10% Dropout ＋ シンプルな Mean Poolingを施すだけで、GLUE、SuperGLUE、および MS MARCO ランキングタスクにおいて同規模の T5 や RankT5 を上回る性能を達成。後の **Gemini Embedding** のアーキテクチャ設計の直接の理論的・実験的基盤となった。

---

## 背景

言語モデルの研究開発は自己回帰型（Causal / Decoder-only）トランスフォーマーを中心に劇的にスケールし、Gemini や Gemma、Llama 等の強力なモデルが生み出された。しかし、**テキスト分類、スコア回帰、文書ランキング（Cross-Encoder）、密埋め込み（Dense Embedding）**といった非生成的な判別タスクにおいては、依然として BERT、RoBERTa、DeBERTa、T5-encoder などの「エンコーダ構造」が主流の座を占め続けていた。

この乖離が生じる理由は、デコーダモデルが「Next-Token Prediction（次トークン予測）」に特化して因果マスク（左から右への一方向注意）で事前学習されているためである。

Google の研究チームは、「**スケールしたデコーダ LLM の膨大な知識を、エンコーダ（判別モデル）として最大限引き出すには、どのようなアーキテクチャ改変と訓練レシピが最適なのか？**」を体系的に解明するため、Gemma-2 を用いた包括的なアブレーション研究を実施した。

---

## 手法

Gemma デコーダの重みで初期化し、分類・回帰・ランキングに特化したヘッドを結合してファインチューニングを行う。

```
[ 入力トークン列: x_1, x_2, ..., x_L ]
       │
       ▼
┌───────────────────────────────────────────────────────────┐
│ Gemma Transformer (因果マスクを解除した Bidirectional Attention) │
└───────────────────────────────────────────────────────────┘
       │  隠れ状態系列: H ∈ R^(L × D)
       ▼
┌───────────────────────────────────────────────────────────┐
│ Pooling Layer (Mean Pooling または Last-K Token Pooling)   │
└───────────────────────────────────────────────────────────┘
       │  集約固定長ベクトル: P ∈ R^D
       ▼
┌───────────────────────────────────────────────────────────┐
│ Randomly Initialized MLP (Dropout 10% 適用)                │
└───────────────────────────────────────────────────────────┘
       │
       ▼
[ 分類ロジット / 回帰スコア / ランキングスコア ]
```

### 1. アテンションマスクの変更（Bidirectional Attention）
- デコーダの因果マスク（各トークンが自身と過去トークンのみを参照）を撤廃。
- 全トークンが前後すべての文脈を同時に参照できる**完全可視の双方向アテンション（Bidirectional Masking）**を適用。

### 2. プーリング戦略（Pooling Strategies）の系統的比較
可変長系列 $H \in \mathbb{R}^{L \times D}$ を固定長ベクトル $P \in \mathbb{R}^D$ に集約する手法を比較：
1. **First-K Token Pooling**: 先頭 $K$ トークン（BERT の `[CLS]` 類似）を抽出。
2. **Last-K Token Pooling**: 末尾 $K$ トークン（文末 `[EOS]`）を抽出。因果アテンション時のデコーダ特性に適合。
3. **Mean Pooling**: 全トークンの隠れ状態の単純平均 $P = \frac{1}{L}\sum_{l=1}^L H_l$。
4. **Attention Pooling（パラメータ追加型）**:
   - **KV-Probe**: 入力を Query 行列 $Q \in \mathbb{R}^{L \times D}$ とし、学習可能な潜在変数 $K, V \in \mathbb{R}^{V \times D}$ で集約。
   - **Query-Probe (Perceiver IO 型)**: 入力を Key/Value 行列 $K, V \in \mathbb{R}^{L \times D}$ とし、学習可能な潜在 Query $Q \in \mathbb{R}^{V \times D}$ で集約。

### 3. ドロップアウト正則化（Dropout）の導入
- 近年の巨大デコーダ LLM は、データ規模の大きさから事前学習時に Dropout=0 とすることが標準となっている。
- しかし、エンコーダ下流タスクはデータ数が限定されており、確定的損失（Cross-Entropy / MSE）で学習するため過学習（Overfitting）を起こしやすい。
- 本手法では、**アテンションの Softmax 後および Feed-Forward Network（FFN）の出力部に 10%（rate = 0.1）の Dropout** を注入。

### 4. パディング戦略（Padding Strategy）
- デコーダで一般的な **Left Padding** と、エンコーダで一般的な **Right Padding** を比較検証。

### 5. ランキングタスク（Listwise Ranking）への適応
- クエリ $q_i$ と $M$ 個の候補文書 $(d_{i1}, \dots, d_{iM})$ に対し、入力形状 $[B, M, L]$ を $[B \times M, L]$ にフラット化して Gemma Encoder に入力。
- 出力スコアを $[B, M]$ に再整形し、**Listwise Softmax Cross-Entropy 損失**（LambdaMART や RankT5 と同等のランキング損失）で最適化。

### 主要アブレーション分析（重要な設計指針）

#### 1. プーリング戦略の比較（Table 5）
双方向アテンション下での GLUE 平均スコア：

| モデル | First-K | Mean Pooling | Attention Pooling (Q) | Attention Pooling (KV) | Last-K |
|---|:---:|:---:|:---:|:---:|:---:|
| **Gemma-2 2B** | 88.7 | **89.4** | 89.0 | 89.0 | 89.1 |
| **Gemma-2 9B** | 90.4 | 89.7 | 90.7 | 90.6 | **90.9** |

> **知見:** パラメータを追加して学習させる Attention Pooling は、小〜中規模データセットでは過学習や不安定化を招き、スコアが伸びない。**パラメータフリーな「Mean Pooling」または「Last-K」が最も高精度かつ安定的**である。

#### 2. アテンションマスクの比較（Table 6）

| モデル | 双方向アテンション (BiDi) | 因果アテンション (Causal: Mean) | 因果アテンション (Causal: Attention) | 因果アテンション (Causal: Last-K) |
|---|:---:|:---:|:---:|:---:|
| **Gemma-2 2B** | **89.4** | 84.5 | 86.0 | 88.6 |
| **Gemma-2 9B** | **90.9** | 87.5 | 88.4 | 90.4 |

> **知見:** 因果マスクから双方向マスクへ切り替えるだけで、全タスクで一貫して性能が向上する。因果マスクのまま使用する場合は、全履歴を参照可能な Last-K のみが辛うじて機能する。

#### 3. ドロップアウト率の比較（Figure 2 & Table 10）
- Dropout 率を 0.0 $\to$ 0.05 $\to$ **0.1** と引き上げることで、GLUE スコアが明確に向上。
- 0.1 を超える（0.15 や 0.2）とアンダーフィッティングにより性能が低下。**0.1（10%）が最適値**。

#### 4. パディング方向の比較（Table 7）
- Left Padding（89.4 / 90.8）と Right Padding（89.4 / 90.9）の間で統計的な有意差はなし。双方向アテンションであればパディング方向に頑健。

## 貢献と限界

### 貢献
- **Decoder $\to$ Encoder 転換レシピの体系化**: デコーダ LLM を判別モデルへ適応させる際の標準プラクティス（双方向化 ＋ Mean Pooling ＋ 10% Dropout）を確立。
- **MLM 事前学習の不要性を証明**: T5 のような事前のマスク言語モデリング（MLM）再事前学習を行わず、デコーダ重みから直接ファインチューニングするだけで、SOTA なエンコーダ性能に到達できることを実証。
- **後発モデルへの波及**: この知見（特に双方向化と Mean Pooling の有効性）は、同研究グループが手掛けた **Gemini Embedding**（2025年3月）の基本アーキテクチャとして直接採用された。

### 限界
- **GLUE 規模の制約**: 論文中でも言及されている通り、プーリングの優劣評価は GLUE（数十万件規模）に基づいているため、数億件規模の対照事前学習を行うケースでは Attention Pooling の再評価が必要な可能性がある。
- **推論レイテンシ**: 2B / 9B というサイズは、従来の BERT（110M）と比較してメモリ消費と推論コストが大きいため、実運用には量子化や高速化の工夫が求められる。
