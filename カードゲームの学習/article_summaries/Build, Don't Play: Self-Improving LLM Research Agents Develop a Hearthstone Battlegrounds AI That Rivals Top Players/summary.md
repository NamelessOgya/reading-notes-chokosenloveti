# Build, Don't Play: Self-Improving LLM Research Agents Develop a Hearthstone Battlegrounds AI That Rivals Top Players

- **著者:** Changlian Ma, Limin Wang（Nanjing University / Shanghai AI Laboratory）
- **arXiv:** [2610.33845](https://arxiv.org/abs/2610.33845)（NeurIPS 2026 preprint 形式）
- **コード:** [MCG-NJU/AutoTavern](https://github.com/MCG-NJU/AutoTavern)（TavernBench / TavernGym を公開予定）

## 一言でいうと
LLMに **ゲームを直接プレイさせる（Play）** のではなく、LLM研究エージェント群に **シミュレータとRLエージェントを作らせる（Build）** ことで、Hearthstone Battlegrounds（8人制オートバトラー）のライブラダーでサーバー上位10人を上回る成績のAIを **20日間・人間メッセージ418件のみ** で構築した。フロンティアLLMは同じ判断を直接させると正答率・速度ともに大きく劣る ⇒ 「LLMはプレイするよりも、作るほうがはるかに上手い」。

## 背景
- 囲碁・StarCraft II・Dota 2・麻雀・Stratego 等の超人的ゲームAIは、いずれも **大規模な人間専門家チーム** が環境構築・学習アルゴリズム設計・シミュレータと実環境のズレの修正を担ってきた。
- 一方、LLMエージェントで研究自体を自動化する試み（AI Scientist、AlphaEvolve、MLE-bench 等）は、ベンチマークタスクや論文査読での評価に留まり、「**生データから出発して、実世界で人間と渡り合うシステムを作れるか**」は未検証だった。
- 対象の **Hearthstone Battlegrounds** は以下の理由で難しい：
  - 8人対戦・確率的なショップと戦闘・7人の相手に関する隠れ情報・共有カードプール
  - 1ゲーム約15ターン・約450原子行動、報酬は最終順位（1〜8位）のみ
  - 978個のゲームオブジェクト（ミニオン・ヒーロー・トリンケット・呪文）が相互作用し、パッチ毎に変化
  - 忠実なシミュレータが存在しない（既存研究は簡略版シミュレータ上のMCTSや戦闘フェーズのみのツール）

## 手法

### 1. AutoTavern：現実に錨を下ろした自己改善型研究システム
中核思想は **Reality-anchored self-improvement**。エージェントが最適化するプロキシ（シミュレータ・対戦相手モデル・評価試験）を一定周期で実ゲームに再アンカーする。

**問題設定:** 反復 $t$ の研究状態を、環境 $E_t$・対戦相手モデル $O_t$・試験 $X_t$・方策 $\pi_t$、さらに研究プロセス自体（メモリ $M_t$、ゲート $G_t$）とする。真の目的はライブラダーでの期待順位 $J(\pi)$ だが、遅く高コストなので、ループ内ではプロキシ $\hat J(\pi; E_t, O_t, X_t)$ しか改善できない。ここから2つの失敗モードが生じる：
- **Proxy drift:** $E_t$ や $O_t$ の誤りを方策が悪用し、$\hat J$ は上がるが $J$ は上がらない → **Reality loop** で対処
- **False findings:** ノイズ・リーク・選択バイアスを結果として記録してしまう → **Verification gates** で対処

**構成要素:**

| 要素 | 内容 |
| :--- | :--- |
| ロールエージェント | Research lead / Environment / Training / Opponent modelling / Evaluation & audit / Deployment の6役 + 短命サブエージェント |
| 型付き研究メモリ | エージェント同士は直接会話せず、バージョン管理された型付きストア（発見台帳・ルール決定レジストリ・引継ぎノート・実験レジストリ・教訓ストア）のみで連携。発見は削除せず、訂正は過去エントリを指す新エントリとして追記 |
| 5つの検証ゲート | **G1 build**（全テスト通過）/ **G2 contract**（モデルと学習時シミュレータビルドを紐付け）/ **G3 comparison**（同一ビルド・複数seedでのみ比較）/ **G4 delivery**（選択に使っていない未見seedで再確認）/ **G5 reality**（ライブで対戦し、その試合をシミュレータでリプレイ） |
| Reality loop | ライブ試合ログをシミュレータで再生し、ズレをルール・入力エンコーディング・対戦相手の修正に変換（20日で **184件の修正**） |
| 自己改善 | 捕まえた誤りを「教訓（全セッション開始時に読み込み）」か「新しいゲート」に変換 → 同じ誤りに二度コストを払わない |

**1反復のサイクル（Algorithm 1）:** Observe → Diagnose → Plan → Implement → Train → Evaluate → Deploy → Reflect。訓練ループ（秒〜分）・研究ループ（時間）・ラダーループ（日）の3時間スケールで回る。人間は「目標設定」と「曖昧なメカニクスの裁定」のみ担当。

### 2. TavernGym：実ゲームの忠実な再現シミュレータ
- Rust製エンジン（約63k行、うちカードスクリプト27k行）+ 薄いPythonバインディング
- 各カードはイベントフックのテーブル、状態はエンティティのアリーナ（コピー安価・シリアライズ可能）、乱数は単一seed ⇒ seedと行動列でゲームをビット単位で再現
- パッチ36.6.3の **全978オブジェクトを実装**、検証記録375件・確定ルール決定220件
- **1コアで190〜280ゲーム/秒**（8人戦フルゲーム）、終盤戦闘は5.2〜7.6万回/秒
- RLインタフェース：**245離散行動** + 厳密な合法手マスク、プレイヤー視点観測（相手のウォーバンドは最後に戦った時の状態のみ）

![TavernGymの構成](./images/figA_engine.png)

### 3. TavernAgent：ライブゲームをプレイするRLエージェント
**モデル:** エンティティTransformer（[図](./images/figA_model.png)）
- 自分のミニオン・手札・酒場のオファー・保留中の選択・相手を各1トークン（最大56 + グローバル1）
- カード表現 = ID埋め込み + 静的特徴量（ティア・スタッツ・種族・キーワード）の射影 + **ルールテキスト埋め込み**の射影（レアカードの初期表現を良くする）
- ポインタヘッドで245行動のlogit、価値ヘッド、補助の順位ヘッド（d=384, 8層, 8ヘッド, 18Mパラメータ）

![TavernAgentのネットワーク](./images/figA_model.png)

**学習:** PPO、終端の順位効用、$\gamma=1.0$。1反復あたり約100万判断、1ステージ300反復（約3.1億判断・57万ゲーム）を、前ステージから **KLアンカー** 付きで継続。カリキュラムは「簡略ルール → 全コンテンツ → プレイヤー視点 → 1位目標 + 人間統計に合わせた相手 → ライブラリ相手」。

**Reality-calibrated opponents（自己対戦ではない）:** 学習者は7つの「ライブラリ席」と対戦する。各ターン、トップ人間プレイヤーの統計から作った盤面ライブラリから、**ライブで実際に出会った相手** に合わせてターン毎に再較正した盤面を引く。これが **単一で最大の改善** だった。

| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| ランダム合法手 | 7.97 | 0.0 | 0.0 | 7.97 | 0.0 | 0.0 |
| スクリプトbot | 7.54 | 0.0 | 0.5 | 7.61 | 0.0 | 0.2 |
| TA-1（初版） | 3.40 | 1.9 | 83.4 | 4.07 | 1.1 | 65.4 |

- 人間は「AIが指名したショートカットキーを押すだけ」（公式プラグイン機能）で、判断はすべてAI
- Day 5〜18 の392試合でレーティングが **6,000 → 14,007**、最終的に約15,000（サーバー上位100位）
- 最新版（TA-19〜23）: 平均順位2.37、1位32.6%、Top-4 91.3%

**4つの知見:**
1. **LLMエージェントが作ったシステムが最強のプレイヤー:** TavernAgent 91% vs 最良LLM 63%。
2. **レイテンシがLLMのライブプレイを不可能にする:** 1秒制約下ではTavernAgent 90%、他LLMはほぼ0%。さらに1ターンに数十の判断が連鎖するため、誤りは平均化されず **複利的に計画を崩す**。
3. **ルールを読めることとプレイできることは別:** フロンティアLLMはルール実行タスクでは90%超だが、同じルールに基づくプレイタスクでは大きく劣る。
4. **ゲームの判断は戦闘計算とは別:** プレイアウトで採点した戦略タスクで TavernAgent 75% vs 最良LLM 54%。
- 補足：LLMにTavernGymをツールとして与えると大半のギャップが埋まる（GPT-6 Astra 62%→97%）。⇒ 弱点は「頭の中でのシミュレーション」。

## 自己改善から得られた教訓（Lessons）
シミュレーション上の指標では見えず、Reality loopとゲートが捕まえた6つの誤り：
1. **コピーしたゲームは未来をリークする:** ゲームコピー上の探索で1位率+23.6ptに見えたが、乱数状態ごとコピーしていたため未来のショップ・戦闘結果が見えていた。サンプル毎に再seedすると効果は消失（−0.65±1.14pt）→ 常設ルール化。
2. **2つの誤りが打ち消し合う:** 試験の終盤相手が強すぎ、かつエージェントの成長が過大評価されていたため、偶然ライブと一致していた。
3. **Winner's curse:** 多数のスナップショットから最良を選ぶと利得を過大評価（選択seedで+1.2〜2.1pt、未見seedで−0.7pt）→ **G4ゲート** 新設。
4. **出会う相手で較正せよ:** ライブラリの強さは一様サンプルではなく学習者が実際に出会う相手で測る → 常設ルール化。
5. **シミュレーションが褒めるものをラダーが咎める:** TA-10は試験の1位率をほぼ倍増（12.8%→24.2%）したが、ラダーでは32試合でレートが8,968→7,658に低下。序中盤の弱点を試験が隠していた。
6. **2つのエンコーダが乖離する:** コントローラとシミュレータでトリンケット選択後の入力フラグのエンコードが異なり、ライブでのみ全ウォーバンド売却が頻発 → エンコーダのビット単位比較を **G2ゲート** に追加。

### 学習インフラと学習時間の詳細
**インフラ（論文の付録「Compute resources」より）**
- 本線学習：**NVIDIA H200 × 8 + 128 CPUコア**
- シミュレータ（TavernGym）はRust製でCPU上で動作（1コアで8人戦を毎秒190〜280ゲーム）→ 環境ロールアウトはCPU、方策更新はGPUという分担

**GPU時間の内訳**

| 用途 | GPU時間 |
| :--- | :--- |
| 公開した23ステージ（TA-1〜TA-23）の学習 | 約1,900 |
| 探索・アブレーション・途中で捨てた学習 | 約16,700 |
| 評価・分析 | 約1,300 |
| **合計** | **約19,900** |

※ GPU時間 = GPU枚数 × 経過時間。各実験は設定上のサイズで数えた値。

**GPU時間の読み方（推算を含む）**
- 「1,900 GPU時間」は8枚で1,900時間という意味ではない。8枚なら 1,900 ÷ 8 ≈ **約240時間（約10日）**。
- 各ステージは前のステージのモデルから学習を続ける（最初の100イテレーションはKLアンカー付き）。なので実質的には **1本のモデルを継ぎ足しながら約240時間学習し、途中で23回スナップショットを公開した** と考えるのが近い。最終版TA-23は累計約1,900 GPU時間分の学習を受けている。
- 1ステージあたりは 1,900 ÷ 23 ≈ **約83 GPU時間**、8枚で **約10時間**。1ステージは300イテレーション、約3.1億判断、約57万ゲーム。
- 期間：TA-1が4日目、TA-23が18日目 → エージェントの改良期間は **約2週間**。
- 合計19,900 GPU時間を8枚で回すと約104日かかり、20日に収まらない。探索などの学習は本線とは別のGPUで並行していたと考えられるが、その構成は論文に書かれていない。

> [!NOTE]
> 「1ステージ約10時間」「23ステージは連続した1本の系列」は、どちらも論文の数値から計算した推算。ステージごとの実時間は論文に書かれていない。TA-11の「専門モデルの統合」のように、系列が単純な一本道でない箇所もある。
>
> 比較：Hearthstoneの過去研究（Mastering strategy card game）は1つのモデルを16〜23日学習していた。本研究は同じくらいの期間で23回の改良を回している。

## 付録の補足的な分析
- **モデルサイズ:** 3.5M / 8M / 18M を比較し、18Mが最良（[tables_source.md](./tables_source.md) の model-size 表）。
- **同一ロビーでのバージョン対戦:** 8バージョンを同じロビーに入れるとTA-23が1位26.2%（公平分の約2倍）。
- **判断の価値（[図](./images/figA_decision_value.png)）:** Dark Gift・Discover・対象選択をランダム化するとそれぞれ1.4〜1.9順位悪化、トリンケット選択は0.5、ヒーローパワーは0.25。
- **ヒーロー別強さ（[図](./images/figA_hero_table.png)）:** 人間の評価とほぼ無相関（Pearson r=0.13）。人間が弱いと評価するヒーロー（Fungalmancer Flurgl 等）で強く、複数ターンにわたる計画を要するヒーロー（The Jailer, Alexstrasza 等）で相対的に弱い。
- **ウォーバンド強度（[図](./images/figA_turn_strength.png)）:** 最終版はターン9まで人間上位1%と同等、ターン11以降は2〜8倍の総攻撃力・体力を構築。

## 所感・カードゲーム学習の観点からのポイント
- 既存のHearthstone研究（[Mastering strategy card game (Hearthstone) with improved techniques](../WIP_Mastering%20strategy%20card%20game%20(Hearthstone)%20with%20improved%20techniques/summary.md) など）が **自己対戦（OSFP）+ 分散RL** を工夫の中心にしたのに対し、本研究は学習器自体は標準的なPPO + Transformerで、**「訓練世界（シミュレータ・相手分布）を現実に合わせ続けること」** に工夫の重心がある。
- カード表現に **ルールテキスト埋め込み** を加える点は [Cardsformer](../WIP_Cardsformer:%20Grounding%20language%20to%20learn%20a%20generalizable%20policy%20in%20hearthstone/summary.md) と同じ方向性で、新カード・レアカードへの汎化に効く。
- 多人数・非ゼロサム（順位効用）環境では自己対戦の均衡概念が使いにくく、**人間分布に較正した相手ライブラリ** が実用解となっている点は、MTG等の多人数・メタゲームが強い環境にも示唆的。
- 「LLMがエージェントを作る」研究運用（型付きメモリ・検証ゲート・教訓化）は、カードゲームに限らず研究自動化の設計パターンとして参考になる。
- 注意点：対象は1ゲーム・1パッチ。ライブでの比較は公開リーダーボードのレート変化からの推定順位という間接指標であり、直接対戦ではない。
